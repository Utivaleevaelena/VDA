# THE NEXT TABLE — сайт и платформа бронирования

Полноценное веб-приложение по мастер-промпту (`THE_NEXT_TABLE_Master_Prompt.pdf`) и UI-киту (`THE_NEXT_TABLE_UI_ASSETS`).
React + TypeScript + Vite (фронтенд), Node + Express (сервер, бронирование, админка, почта), **Supabase** (PostgreSQL + приватное хранилище аватаров).

## Запуск

```bash
cd app
npm install
npm run dev          # API :8787 + сайт http://localhost:5173
```

При первом запуске на пустой БД (только в dev) создаются: админ из `.env`, 3 «пилотные» темы с датой «уточняется»
и один явно помеченный **DEMO-стол** с вымышленными участниками (аватары из UI-кита) — чтобы всё можно было потрогать.
Перед боевым запуском их нужно скрыть/удалить в админке; в `NODE_ENV=production` демо-данные не создаются.

- Сайт: `http://localhost:5173` · Админка: `http://localhost:5173/admin`
- Логин админа — `ADMIN_EMAIL` / `ADMIN_PASSWORD` из `.env` (файл не коммитить). Другой админ: `ADMIN_EMAIL=… ADMIN_PASSWORD=… npm run admin:create`.
- Продакшн: `npm run build && npm start` (Express отдаёт `dist` и API на одном порту). Задайте `PUBLIC_URL` (ссылки в письмах). Нужны `DATABASE_URL`, `SUPABASE_URL`, `SUPABASE_SERVICE_KEY` (см. `.env.example`); таблицы и приватный бакет `avatars` создаются автоматически при старте.

## Что НЕ подключено и какое действие нужно

1. **Транзакционная почта.** Без ключа письма **не отправляются** — они пишутся в журнал со статусом «не отправлено», в админке виден статус. Нужно: завести Resend (или аналог), подтвердить домен, задать `RESEND_API_KEY` и `MAIL_FROM`. Пока почта не подключена, организатор может подтвердить email заявки вручную кнопкой в админке. Шаблоны для всех 9 типов писем на трёх языках готовы (`server/mail.ts`); письмо-напоминание за 24 часа шлётся планировщиком сервера.
2. **CAPTCHA** (Turnstile/hCaptcha) не подключена — работают лимиты и honeypot.
3. **Юридический текст.** `Политика конфиденциальности` — рабочий черновик на 3 языках. Перед запуском нужна проверка юристом; сайт нигде не заявляет соответствие GDPR. Сроки хранения данных не определены.
4. **Хостинг сервера.** Данные уже в Supabase (Postgres, RLS включён на всех таблицах без политик — Data API не отдаёт ничего; ключ `service_role` используется только на сервере). Сам Node-сервер нужно развернуть (Railway, Fly.io, VPS) с теми же переменными окружения.
5. **Реальные события.** Реальных дат и участников в коде нет — создайте события в админке («События → Новое событие»), потом «Опубликовать».

## Отступления от спецификации (сознательные)

- Шрифт заголовков — **Playfair Display** вместо Instrument Serif: у Instrument Serif нет кириллицы. Manrope — как в ТЗ. Шрифты self-hosted (без Google Fonts — это важно для GDPR).
- Вместо «Supabase-клиент + Edge Functions» — свой Node-сервер поверх Postgres Supabase: вся логика бронирования и права доступа проверяются на сервере.
- Вместо Tailwind — обычный CSS на токенах палитры (Ivory / Ink / Oxblood / Sage / Cream).
- Видео-ссылка встречи хранится в событии и отдаётся только подтверждённому участнику (в письме и на его странице).
